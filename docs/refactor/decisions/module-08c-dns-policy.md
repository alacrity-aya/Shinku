# Module 8C DNS Policy Decisions

## Segment 19: Module 8C DNS Policy Engine

Decisions:

1. Module 8C delivers only the Response side in C++. `classify_response()` is the engine's production entry point and there is no `classify_query()`, because the eBPF Backend classifies Queries in XDP to decide hit or miss and no Host Runtime object would ever call one. This matches the `CONTEXT.md` definition of DNS Policy, which was already response-only.
2. Cacheable Query Profile membership on the Query side is a backend-neutral rule set verified by shared vectors, following the ADR-0013 pattern rather than a parallel C++ implementation. A C++ classifier with no production caller would exert no correctness pressure on the XDP implementation; only shared vectors do that.
3. The 8C module doc wording that described DNS Policy as classifying each Query is corrected. The rule ownership is unchanged: only a Query inside the Cacheable Query Profile may establish a Pending Query.
4. `DnsPolicy` is a class constructed from `max_response_bytes` and `cache_negative`, exposing `classify_response(std::span<const std::byte> message, CacheNamespace ns) noexcept -> std::expected<CacheCandidate, BypassReason>`. It takes no canonical name, because the Response echoes the question and TC already validated that it matches the Pending Query, and it takes no current time, because a Cache Candidate carries TTL rather than an expiry.
5. The TTL offset scratch is a `DnsPolicy` member. The returned Candidate borrows it and stays valid until the next `classify_response()` call, which is the same synchronous borrow contract the response bytes already have. `kMaxTtlOffsets` belongs to 8C rather than the 8B contract and is derived from the 512-byte ceiling as `(512 - 12 - 5) / 11 = 45`, which is 90 bytes inline and allocation-free.
6. `BypassReason` carries a specific reason, unlike the reason-free `Rejected` of decision 42. A Store rejection reason describes a private eviction strategy that changes with the algorithm, while a Bypass reason is a stable DNS semantic fact and the only diagnostic an operator has when a deployment caches nothing. Module 8C returns it; Module 10 decides how it is presented.
7. Module 8C writes a new C++ DNS wire parser instead of adapting `src/core/dns_parser.c`. Decision 58 removed response rebuilding, ECS is Pass-through, and the remaining parser is a bounded structural scan with different ownership and output. The legacy C parser remains unchanged as a transitional path and is deleted with that path in 8E.
8. Wire parsing and DNS Policy judgment are separate layers joined by an explicit `ParsedResponse` contract. The parser reports structural `ParseError` values and extracts wire facts without deciding Cache Entry Kind or cache eligibility; the policy layer consumes a valid `ParsedResponse` plus configuration and correlation context to produce either a `CacheCandidate` or `BypassReason`. The production `classify_response()` facade composes both layers rather than exposing two calls to Backend composition.
9. `ParsedResponse` is a non-owning, allocation-free per-call view over the input message and the `DnsPolicy` TTL-offset scratch. Parser-focused tests and fuzzing target malformed lengths, names, compression, and RR boundaries; policy-focused tests construct valid `ParsedResponse` values directly to exercise DNS semantics without encoding wire packets. Composition tests cover the facade from bytes to final classification.
10. The C++ wire parser supports RFC 1035 compression in every RR owner name and in every RDATA domain name that 8C interprets, including CNAME targets and SOA MNAME/RNAME. It follows pointers only for bounded validation and never decompresses, rebuilds, or modifies the verbatim Response Template.
11. Compression validation requires a complete two-octet pointer whose target is inside the DNS message and strictly precedes the pointer, labels no longer than 63 octets, an expanded wire name no longer than 255 octets, termination at the root label, a fixed traversal bound, and rejection of reserved `01` and `10` label prefixes. Violations are structural `ParseError` values; the backward-target rule excludes pointer cycles without maintaining a visited set.
12. The Response Question must use an uncompressed wire name for Cache Fill. A compressed Question can be a structurally valid DNS message, so it is classified as `BypassReason::UnsupportedQuestionEncoding` rather than `ParseError`; this preserves the invariant that a Cache Hit can substitute the current Query Question without changing message length, RR offsets, or compression-pointer targets.
13. A cacheable Response must have `QR=1`, standard `QUERY` opcode, `QDCOUNT=1`, `TC=0`, `ARCOUNT=0`, an `A/IN` Question, and base RCODE `NOERROR` or `NXDOMAIN`. A structurally valid message outside this Response Profile is a reasoned Bypass; truncated fields, inconsistent lengths, and RR-boundary violations are `ParseError` values.
14. For `A/IN`, DNS Policy validates a unique CNAME Chain from the Question Name independently of Answer RR wire order. The chain may end in one or more A records for one terminal owner. A CNAME cycle, conflicting targets, CNAME and A at the same owner, an unrelated Answer A/CNAME, or an unsupported Answer type is a Bypass rather than a Cache Candidate.
15. `NOERROR` with a reachable terminal A is `Positive`. `NOERROR` without a terminal A but with a valid Authority SOA is `NoData`, including a CNAME Chain whose final name has no A. `NXDOMAIN` without a terminal A but with a valid Authority SOA is `NxDomain`, including NXDOMAIN after a CNAME Chain. A negative result without SOA, a referral, or an `NXDOMAIN` Response with a reachable A is a Bypass.
16. `ANCOUNT` alone never determines Cache Entry Kind. Query Correlation establishes exchange consistency only; it does not prove that Answer owners and CNAME targets semantically answer the Question. Full Answer validation remains in 8C and runs only on the bounded Cache Fill Path.
17. Module 8C trusts successful TC Query Correlation and does not receive a Pending Query fingerprint or original Question for a second consistency comparison. It still parses and validates the Response Question to enforce the Response Profile, construct `CanonicalDnsName` and `CacheKey`, and anchor CNAME Chain validation. Shared fingerprint code, shared vectors, and TC-to-Host integration tests verify the correlation boundary instead of duplicating it inside DNS Policy.
18. Module 8C uses a Cache-owned layered layout. Public cache-admission types and composition live as `src/cache/dns_policy.{h,cc}` and `src/cache/bypass_reason.h` in `shinku::cache`; wire parsing internals live under `src/cache/dns/` in `shinku::cache::dns`, including `wire_parser`, `parsed_response`, and `parse_error`. The existing `CanonicalDnsName` remains in `shinku::cache`. A general `src/dns/` module is deferred until a non-cache consumer creates a real reuse boundary.
19. Query Eligibility uses language-neutral DNS-message vectors under `tests/vectors/query_eligibility/`. Each TOML vector contains the DNS Query wire bytes, expected `eligible` or `bypass` classification, and the expected logical Question fields only when eligible; it does not contain Ethernet, IP, UDP, packet-buffer, physical fingerprint, or Query-side Bypass reason data.
20. Each Backend wraps the shared DNS message in its own packet representation and verifies the contract at its real Query path. For an eBPF cold-cache vector, eligibility means `XDP_PASS` plus Pending Query creation; Bypass means `XDP_PASS` without an ordinary cache lookup or Pending Query. Backend-specific tests separately cover VLAN, fragmentation, transport lengths, checksums, and other packet-envelope behavior.
21. Query Eligibility coverage starts from one valid uncompressed recursive `A/IN` baseline and mutates one profile condition per vector. It covers header direction and opcode, all section counts, `RD`, `CD`, type, class, Additional Section forms including EDNS/DO/ECS, compressed and malformed QNAMEs, truncation, and field-boundary failures. Module 8C writes the contract vectors without adding a production C++ Query classifier; 8D and future DPDK tests consume them.
22. The wire parser constructs `CanonicalDnsName` and extracts Question type and class into `ParsedResponse`; it does not receive `CacheNamespace` or construct `CacheKey`. After semantic validation succeeds, DNS Policy combines those parsed Question fields with the correlated `CacheNamespace` to construct the `CacheKey` carried by `CacheCandidate`. Backend composition never supplies a preconstructed logical key.
23. ECS Pass-through adds no ECS-specific C++ type or Bypass reason in the MVP. Query Data Planes treat any `ARCOUNT != 0` uniformly as Bypass without parsing EDNS options or creating Pending Query state; an unexpected correlated Response with an Additional Section uses the generic `AdditionalSectionPresent` reason. `EcsCoverage`, ECS prefixes, and variant identity are introduced only with a future ECS-aware Caching design.
24. Module 8C uses layered deterministic tests: wire-parser tests cover structural facts and `ParseError`; policy tests construct `ParsedResponse` values directly; facade tests run real DNS messages through `classify_response()` and verify the final key, kind, lifetime, complete TTL patch plan, verbatim template, and `BypassReason`.
25. The wire parser and `classify_response()` also have coverage-guided fuzz targets. Fuzz properties include termination, memory safety, deterministic output, and in-range TTL offsets for every successful parse. Parser and policy semantics remain covered by deterministic tests rather than treating fuzzing as their only oracle.
26. Fuzzing uses the Clang compiler-rt libFuzzer runtime without adding a project dependency or Meson subproject. Fuzz targets are disabled by default, require a separate Clang build when enabled, and do not alter the normal GCC/AddressSanitizer build or run unbounded work through default `meson test`.
27. A committed seed/regression corpus supplies valid and malformed DNS structures. CI may run a bounded fuzz smoke test; every minimized failure that fixes a distinct behavior is retained as corpus and, where its expected result is meaningful, as a deterministic regression test.
28. Parser scratch uses separate fixed-capacity `ParsedAnswer` and `ParsedAuthority` arrays plus the TTL-offset array rather than one generic `ParsedRr` array, wire-name references, a name-interning table, repeated message scans, or dynamic containers. `ParsedResponse` owns Header and Question facts and borrows the input message and active scratch ranges. The section-specific types keep CNAME data out of Authority facts and SOA data out of Answer facts at compile time. Each array has `kMaxResourceRecords` capacity even though their live counts share the message-wide RR bound; the small one-instance memory cost is accepted for the simpler contract. Resetting the scratch changes only its live counts and never clears the full arrays per Response.
29. `DnsPolicy::classify_response()` keeps the direct `(std::span<const std::byte> message, CacheNamespace cache_namespace)` input instead of adding `CorrelatedResponseView`, a private constructor, or a capability token. Its declaration documents successful Query Correlation as a caller precondition. The eBPF composition path and TC-to-Host integration tests enforce that only a completely matched event reaches this call; C++ does not add a wrapper that can still be constructed incorrectly or duplicate Correlation validation inside DNS Policy.
30. Complete-message framing is split from the configured Cache Response Limit. TC derives the DNS payload length from the validated UDP Length and publishes a packet-ring event only when the complete payload fits the 512-byte event capacity; it never caps or truncates a larger Response. `DnsPolicy` alone turns a complete event larger than `max_response_bytes` into `BypassReason::ResponseTooLarge`. After parsing every Header-declared Question and RR, the wire parser requires its cursor to equal `message.size()` and reports trailing bytes as structural `ParseError`. This keeps every accepted verbatim Response Template fully declared and validated.
31. A negative result after a CNAME Chain remains one verbatim Response Template keyed by the original Response Question; 8C does not decompose it into a CNAME entry plus a terminal negative entry or synthesize a Response from multiple Cache Entries. DNS Policy follows the CNAME Chain only to obtain the terminal negative name and requires exactly one Authority IN/SOA whose owner is a DNS-label ancestor of that terminal name. SOA plus NS is accepted as an RFC 2308 type-1 negative response, while multiple Authority SOAs Bypass. A negative response without SOA does not enter the cache; NXDOMAIN remains an NXDOMAIN response regardless of NS presence, while a NOERROR response with NS and no SOA is a referral. The combined entry lifetime is `min(minimum TTL across every retained RR, selected SOA.MINIMUM)`, and direct Queries for the terminal name do not hit an entry stored for an alias.
32. The wire parser retains detailed internal `ParseError` values for focused tests, fuzzing, and regressions. `classify_response()` maps every such structural failure to the single public `BypassReason::MalformedResponse`; it does not expose a `variant`, duplicate parser members into `BypassReason`, or require Backend composition to understand wire-parser internals. Public Bypass reasons remain stable Policy-level categories. When several conditions apply, classification uses the stable stage order: configured size, complete structural parse, Response Profile, Answer/negative semantics, then configuration and zero lifetime. Tests normally mutate one condition at a time and do not freeze a finer precedence inside one stage.
33. The MVP Query Profile rejects `AD=1` before Pending creation. A cacheable Response requires `QR=1`, standard `QUERY` opcode, `QDCOUNT=1`, `TC=0`, `ARCOUNT=0`, `RD=1`, `CD=0`, and reserved `Z=0`; `AA`, `RA`, and `AD` are retained verbatim and are not independently normalized. Only strict `IN/A` and `IN/CNAME` Answer RDATA and strict `IN/SOA` and `IN/NS` Authority RDATA are supported; Additional must be empty. Known malformed RDATA is a parser `ParseError`, while structurally valid unsupported RR types are Policy Bypasses.
34. Module 8C trusts the correlated local DNS forwarder for DNS answer correctness, but not for producing bytes that are automatically safe to persist and replay. It validates only the invariants required by a `CacheCandidate`: bounded parsing and memory safety, correct `CacheKey` and `CacheEntryKind` derivation, lifetime, complete TTL patch offsets, and exact verbatim-template boundaries. It does not validate DNSSEC, public-address plausibility, SOA server reachability, recursive resolution correctness, or upstream authority. These checks run on the bounded Cache Fill Path, not the XDP Cache Hit Path.
35. Module 8C is a Correlated Verbatim Packet Cache Policy, not a partial recursive resolver or RRset cache. After successful Query Correlation, it strictly validates complete-message wire safety, Question-derived cache identity, every retained RR TTL offset, negative lifetime, template boundaries, and the Cacheable Response Profile, but trusts the DNS Service Endpoint's answer semantics. It does not follow or validate a CNAME chain, require a terminal A, reject an otherwise structurally valid Response because an Answer owner appears unrelated, or whitelist Answer and Authority RR types merely because policy does not interpret them. This supersedes the CNAME-target interpretation in decision 10, decisions 14-16, the CNAME-validation clause of decision 17, decisions 28 and 31, and the RR-schema portion of decision 33 where they require semantic Answer resolution. A CNAME-plus-negative response remains one verbatim entry under the original Question, but terminal-name and SOA-ancestry proof are removed. The parser fact contract and lightweight negative classification/SOA selection are reopened so they can be simplified without restoring resolver behavior. See ADR-0016.
36. Module 8C adopts dnsdist-compatible packet-cache admission semantics without copying dnsdist's best-effort partial parser behavior. Query Correlation plus an uncompressed matching Question establishes identity; Answer and Authority semantics remain opaque. The parser completely traverses every Header-declared RR owner and generic RR boundary, records every non-OPT TTL offset, and computes the minimum wire RR TTL. RR owner compression pointers terminate the encoded owner and are never followed, so only their two-octet wire availability is checked; target range, direction, label boundary, and cycles are irrelevant to 8C. `ParsedResponse` contains Header and canonical Question facts, an optional minimum RR TTL, an Authority `IN/SOA` presence bit, the message view, and the borrowed TTL-offset range, with no Answer or Authority arrays. `NXDOMAIN` comes from RCODE, `NOERROR` with Authority `IN/SOA` is `NoData`, and other admitted `NOERROR` is `Positive`; all kinds use the minimum wire RR TTL, and `SOA.MINIMUM` is not parsed because the DNS Service Endpoint is trusted to have emitted the effective RFC 2308 TTL. A Response with no usable RR TTL Bypasses. This supersedes decision 60 of Segment 15, the RR/RDATA compression requirements of decisions 10-11 in this segment, and resolves the representation and negative-classification questions reopened by decision 35. Trailing-byte handling is resolved separately by decision 37.
37. After completely traversing every Question and RR declared by the DNS Header, Module 8C retains any remaining bytes inside the validated UDP-length payload as an opaque suffix of the verbatim Response Template, matching dnsdist. The suffix is not interpreted as additional RRs, contributes no TTL offsets or lifetime, and is replayed unchanged. A declared Question or RR that crosses the payload boundary still fails structural parsing; this decision permits only bytes after a complete declared message and supersedes the cursor-equality and trailing-`ParseError` clause of decision 30.
38. The backend-neutral `CacheNamespace` stores destination IPv4 and UDP port in host byte order. Packet-ring event fields and the physical eBPF key store those values in network order and use explicit `_be` names or `__be32`/`__be16` types; Backend event composition converts network to host, and the eBPF Store adapter converts host to network. The physical key includes explicit zeroed padding. XDP constructs its lookup namespace by directly copying `ip->daddr` and `udp->dest`, so no byte swap is added to the Cache Hit Path. This also refines Segment 15 decision 81 and ADR-0015.
39. Module 8C implements RFC 2181's 31-bit TTL rule: a received wire TTL with its high bit set is interpreted as the entire value zero, not masked to its low 31 bits, clamped, or used as an ordinary `uint32_t`. Since Cache Entry Lifetime is the minimum across every retained RR in one verbatim template, any such TTL yields a whole-response `ZeroLifetime` Bypass. It is not a structural `ParseError`, and the current upstream Response remains Fail-open and is forwarded normally.
40. Each `DnsPolicy` instance is single-caller and non-thread-safe because it owns mutable TTL-offset scratch. A successful `CacheCandidate` borrows both packet-event response memory and that scratch; Backend composition must pass it to `CacheStore::store()` synchronously before the packet callback returns and before the next `classify_response()` call on the same Policy. Concurrent workers use independent Policy instances, with no mutex on the Cache Fill Path. Asynchronous fill is deferred: a future design must materialize response bytes and offsets into an owned, bounded `FillWork` allocation before callback return, and pool exhaustion drops only the fill attempt.
41. Serialized DNS test fixtures are generated rather than hand-maintained. Standard-library Python packet builders construct DNS Header, Question, RR, SOA, OPT, and ECS structures in network byte order, validate the Cache Hit and Query Eligibility contract sets, and emit one Backend-neutral TOML artifact per set during Meson configuration. C++ and future Backend tests consume those artifacts. Generator source is the contract source of truth; generated TOML is build output and is not committed. No Python third-party dependency or `uv` environment is introduced because the standard library is sufficient.
